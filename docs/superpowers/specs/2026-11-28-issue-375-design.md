## Chosen approach

Human-authored announcements plus machine-checked publication decisions. A checklist alone can miss releases; automatic announcements from arbitrary edits cannot safely distinguish substantive corrections from formatting. Humans decide reader impact, translations, actual dates and exclusion reasons; validation checks coverage and structural consistency. No claim that a passing check publishes anything.

## Publication contract

One append-only decision identifies exact changed question/term records (source path, stable ID, locale and before/after fingerprints), a summary and either a new announcement ID or a nonblank no-announcement reason. One mixed quiz/glossary release can share one announcement. Add glossary category with three localized labels. Existing notices stay untouched and are grandfathered, not fabricated into historical decisions.

A read-only checker takes an explicit known Git base and committed candidate, resolves both, requires distinct commits and an ancestor base, and compares source snapshots. It must reject same-base/candidate and source parsing/Git failures. Decisions already present at base cannot cover later edits; a fresh decision must match the exact transition. Existing base announcements cannot cover a new release. Reject uncovered/duplicate/stale decisions, missing translations, empty notices, invalid/unpublished/future announcements and invalid links. Each release must appear exactly once per locale in the real aggregator.

Use canonical JSON record fingerprints (object key order and top-level record order ignored; strings and nested array order significant). Scan all files beneath question/term content roots; unknown formats or identity ambiguity fail closed. Source move is delete plus add, never ignored. The known base is selected/reviewed externally; the checker cannot establish that an arbitrary caller-supplied Git commit is the organization's approved baseline.

No new dependencies or CI changes. A standalone local command runs using existing tooling. Errors return nonzero and never report covered. No automatic writes or baseline refresh. New public content remains outside this PR; existing announcements and synthetic fixtures exercise the route.
